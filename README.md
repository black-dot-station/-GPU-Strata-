# 他人のGPUで食うStrataはうまい。

自分のRunPodアカウントでGPUを借りて、Ubuntuのデスクトップから使えるアプリです。GPUの空き状況、1時間あたりの料金、予約、起動・停止をひとつのウィンドウで操作できます。VRAM 24 GB以上のNVIDIA GPUを選ぶと、「AIセットアップ」から本家StrataとQwenを接続できます。

## インストール

1. このリポジトリの **Releases** を開き、v1.5.2の **Assets** から `runpod-gpu-desktop_1.5.2_all.deb` をダウンロードします。
2. ダウンロードしたフォルダーで、次のコマンドを実行します。

   ```sh
   sudo apt install ./runpod-gpu-desktop_1.5.2_all.deb
   ```

3. アプリ一覧から **RunPod GPU マネージャー** を開きます。デスクトップ環境にはGTK 4.12以降、WebKitGTK 6.0、GNOMEキーリングとsystemdのユーザーセッションが必要です。AIセットアップが取得するStrataはLinux x86-64版です。

## 最初のGPUを借りる

- 初回は「案内を始める」か「スキップ」を選べます。メニューの「初めてGPUを借りる」からいつでも再表示できます。
- 自分のメールアドレスでRunPodの本人確認を済ませるか、Podsの読み書き権限を持つ自分のAPIキーで接続します。キーはこのPCのキーリングに保存されます。
- 「GPU一覧・予約」で機種と料金上限を選びます。○は「今すぐ起動」、×は「予約して自動起動」です。残高が必要な場合は「RunPodの支払い設定」を開けます。
- 使い終わったら「メニュー」→「Podの電源・状態」→「停止」を押し、停止状態を確認します。**サインアウトしても、稼働中のPodの課金は続きます。**

## 使っていないGPUの自動停止

「Podの電源・状態」の「使っていないGPUを自動停止」がオンのとき、GPU使用率がほぼ0%（GPU 2%以下・CPU 5%以下）の状態が設定した時間（既定5分、2〜30分）続くと、Podを停止して通知します。ウィンドウを閉じていても、systemdのユーザータイマーが1分ごとに確認します。

- 対象はこのアプリが作ったPodと、選択中のPodだけです。
- 起動から3分以内、予約の処理中、使用率を取得できないとき、アプリでPythonファイルの実行やStrataの準備をしている間は停止しません。
- JupyterLabでの軽い作業やチャットの合間も「使っていない」とみなします。止めたくない作業の前は、オフにするか時間を長くしてください。

## SSH接続の確認

「Podの電源・状態」の「SSH接続の詳細」で、接続先、このPCの鍵の指紋、照合に使うPodのホスト鍵の指紋を確認できます。「接続テスト」はアプリと同じ設定でログインし、応答したPod IDを表示します。「接続コマンドをコピー」で、同じ設定の `ssh` コマンドを端末で使えます。

## AIセットアップの動作条件

GPU 1枚あたりの容量で判定します。Podへの直接SSH接続後、CUDA 13対応ドライバー、Compute Capability 7.5以上、空きVRAM 20 GiB以上を確認します。モデルを用意するためのRAMとディスク空き容量もPod側で確認します。Qwenがテスト質問に正答すると、アプリに「応答確認済み」と表示します。実機で推論を確認した機種はRTX 3090 Tiです。

- 自動接続がオンのときは、RAM 62 GB・CUDA 13以上のマシンを条件に発注します。条件に合うマシンがなくRunPodに断られた場合は、同じGPUを通常の条件で1回だけ発注し直します（この場合、RAMが足りずQwenを準備できないことがあります）。
- このPCに保存したQwenを使えないとき（外付けドライブが外れているときを含む）は、PCにダウンロードし直さず、PodがHugging Faceから固定版のファイルを直接取得します。

## ソースからパッケージを作る

Python 3と `dpkg-deb` を用意し、リポジトリのルートで `python3 build_deb.py` を実行すると、`dist/` にインストール用のパッケージができます。
